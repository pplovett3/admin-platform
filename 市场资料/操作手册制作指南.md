# 软件验收文档制作指南（可复用风格规范）

> 本文档总结了 **智能泵站全工况科研虚拟仿真平台 v1.0** 三类验收交付物——**需求文档、测试用例、操作手册**——的统一制作方法与风格规范，供其他软件项目参考复用。
> 把本文件连同 `build_requirements.py` / `build_testcases.py` / `build_manual.py` 一起喂给 AI，并附上目标软件的截图与功能清单，即可生成风格一致的三份验收文档 PDF。
>
> 三份文档共用同一套视觉风格（封面、页眉页脚、配色、字体、表格、提示框），仅在章节模板与内容组织上有所区别，便于成套交付、风格统一。

## 一、整体设计风格（三份文档共用）

### 1.1 视觉调性
- **深色科技风封面** + **浅色正文**，专业、克制、信息密度适中。
- 封面满版深蓝底 + 顶部强调色装饰条 + 居中大标题；正文白底配深蓝页眉、灰色页脚分隔线。
- 强调"图文并茂"：操作手册每章至少 1 张实机截图；需求文档在总体设计与关键模块配图；测试用例以结构化表格为主、辅以少量界面图。

### 1.2 配色规范（可直接复用）

| 用途 | 颜色 | Hex |
|------|------|-----|
| 主色（标题/页眉底/封面底） | 深海军蓝 | `#0B2545` |
| 强调色（二级标题/按钮/装饰条/表头） | 科技蓝 | `#1277D6` |
| 提示框背景/表格隔行 | 浅蓝 | `#EEF3FA` |
| 次要文字/图注/页脚 | 中灰 | `#555555` |
| 分隔线/表格边框 | 浅蓝灰 | `#C9D6E8` |

### 1.3 字体规范（中文）
- **正文**：微软雅黑 `msyh.ttc`（subfontIndex=0）
- **加粗/标题**：微软雅黑粗体 `msyhbd.ttc`（subfontIndex=0）
- **备选**：黑体 `simhei.ttf`（单文件 TTF，最稳妥）
- 注册为可加粗字体族，使 `<b>` 标签生效：
  ```python
  pdfmetrics.registerFont(TTFont("MSYH", r"C:\Windows\Fonts\msyh.ttc", subfontIndex=0))
  pdfmetrics.registerFont(TTFont("MSYHBD", r"C:\Windows\Fonts\msyhbd.ttc", subfontIndex=0))
  pdfmetrics.registerFontFamily("MSYH", normal="MSYH", bold="MSYHBD")
  ```

### 1.4 版式参数（A4 纵向）
- 页面：A4（595×842 pt）
- 页边距：左右各 18mm，上 20mm，下 18mm
- 页眉：深蓝条 14mm，左文档名（粗体）、右一句话副标题
- 页脚：浅灰分隔线 + 左品牌、右页码（`第 N 页`，与目录页码一致）
- **关键**：页脚页码用 `doc.page`（不含封面减 1），确保与目录索引一致。
- 三份文档页眉副标题区分：操作手册=`<软件名>`、需求文档=`Software Requirements Specification`、测试用例=`Test Case Specification`。

### 1.5 通用组件
- **图片**：`img(path)` 读真实尺寸按比例缩放到内容宽度，避免变形。
- **图+图注**：`fig(path, caption)` 用 `KeepTogether` 包裹，防止图在一页、注在下一页。图注格式 `图 X-Y　说明`，居中、灰色、9pt。
- **项目符号**：`bullets(items)` 统一蓝色菱形/圆点。
- **提示框**：`info_box(title, text)` 左色块标题 + 右浅蓝正文。
- **标准表格**：`std_table(data, colWidths)` 深蓝表头 + 隔行底色 + 浅蓝灰边框，`repeatRows=1` 跨页重复表头。

## 二、三份文档的内容结构（章节模板）

三份文档共用「封面 → 目录 → 正文章节 → 附录」骨架，章节按文档类型增删。

### 2.1 操作手册（面向使用者的"怎么用"）

```
封面                    软件名 + 副标题 + "操作手册" + 技术亮点 + 落款日期
目录                    带页码索引的章节列表
第一章 软件概览         功能定位（4 条要点）+ 技术栈 + 一句提示框
第二章 界面布局与导航   主界面全景截图 + 顶栏/侧栏/视口/图表区分点说明
第三章 核心操作流程      按工作流分子节：参数配置 → 启动 → 可视化 → 结果解读
                        每子节配 1 张截图 + 要点列表
第四章～第N章 功能模块   每个独立功能模块单独成章（如"管道壁面律验证""OpenFOAM 三维求解"）
第N+章 数据/计算依据     透明性说明弹窗或数据溯源
第N+2章 报告/导出        导出功能用法
附录 A 模型/资源清单     表格形式
附录 B 公式/参考文献     要点 + 参考文献
```

**写作风格**：第二人称指导操作（"点击…""设置…"）；控件名加粗或「」包裹；每章开头 1 段总述 + 项目符号列表；关键提醒用提示框；图注 `图 X-Y　说明`。

### 2.2 需求文档（面向验收的"要做什么"）

```
封面                    软件名 + "软件需求规格说明书" + 能力概览 + 落款
目录
第一章 文档说明         编写目的 / 适用范围 / 术语缩略语 / 参考文档
第二章 项目概述         建设背景 / 产品定义 / 用户角色（表）/ 运行环境
第三章 系统总体设计     总体架构（配门户截图） / 技术栈 / 模块划分
第四章 功能需求         按模块分子节，每节配"需求条目表"
                        表头：编号 | 需求描述 | 优先级 | 实现状态
                        需求编号 FR-XX，与附录追踪矩阵对应
第五章 非功能需求       性能/可靠/易用/可维护/兼容/安全/可移植（表）
第六章 接口需求         用户接口 / 软件接口 / 硬件接口 / 通信接口
附录 A 需求追踪矩阵     参数要求条目 → 需求编号 → 状态（全量覆盖表）
附录 B 术语表           术语 + 释义
```

**写作风格**：客观陈述；功能需求用表格逐条列出（编号+描述+优先级+状态）；每节开头 1 段概述说明该模块能力；关键模块配 1 张实机截图佐证"已实现"；附录 A 追踪矩阵是验收核心，确保每条参数要求都有 FR 编号覆盖。

### 2.3 测试用例（面向验收的"怎么验"）

```
封面                    软件名 + "测试用例集" + 覆盖范围 + 落款
目录
第一章 测试概述         测试目的 / 范围 / 策略 / 通过准则 / 缺陷分级
第二章 测试环境         软硬件环境（表）/ 测试数据 / 测试工具
第三章 功能测试用例      按模块分子节，每条用例一个"用例块"
                        用例块 = 标题条 + 属性表（编号/名称/前置/优先级/关联需求）
                                 + 步骤表（步骤号/操作/预期）+ 预期总结行
第四章 非功能测试用例   性能/可靠/易用/兼容/安全/可移植（汇总表）
第五章 接口测试用例     REST API / 算例链路 / 导出格式（表）
第六章 测试结论模板     执行汇总表 + 遗留缺陷清单 + 结论判定
附录 A 测试用例清单汇总 全部用例编号/名称/模块/关联需求/优先级（表）
附录 B 缺陷分级标准     S1~S4 定义 + 用例状态定义 + 记录要求
```

**写作风格**：用例编号 TC-XXX 与需求 FR-XX 一一对应；每条用例含前置条件、分步操作、预期结果、关联需求；用例块用 `KeepTogether` 包裹避免跨页拆散；非功能与接口用例可用汇总表精简呈现；结论模板预留空格供填写实际数据。

## 三、截图获取工作流（操作手册/需求文档配图）

### 3.1 工具
- 浏览器自动化截图（Cursor 的 `cursor-ide-browser` MCP：`browser_navigate` → `browser_take_screenshot`）。
- 或人工截图：全屏窗口截图后裁剪，保存为 PNG。

### 3.2 截图清单规划
**先列清单再截**，确保覆盖每个功能态：
1. 主界面全景（设置态，未运行）
2. 各主要模式/视图切换后的全景
3. 运行中态（流场/数据已渲染，最有视觉冲击力）
4. 关键弹窗/详情面板（模态窗单独截一张）
5. 导出/报告产物预览
6. 门户主页与各模块详情页（需求文档总体设计配图）

### 3.3 截图规范
- **统一分辨率**（如 1920×1080 全窗口），保证 PDF 内缩放后宽度一致。
- **命名有序**：`01_xxx.png`、`02_xxx.png`…，与章节顺序对应；三份文档可共用 `shots/` 目录。
- **状态干净**：截图前关闭无关弹窗、暂停会闪烁的指示灯、确保数据已加载。
- **运行态优先**：带彩色流场/图表的截图比空设置态更有说服力，多用。
- 存放目录：`manual/shots/`。

### 3.4 本地起服务截图
若目标软件已部署但现场网络不可达，可在本地启动服务后截图：
- 前端：`npm run dev`（Vite 默认 5173）或 `python -m http.server <port>`（静态门户）。
- 后端：`python -m uvicorn app:app --host 0.0.0.0 --port 8000`（注意 `app.py` 若无 `__main__` 入口，需用 uvicorn 启动）。
- 浏览器导航到 `http://localhost:<port>/` 截图即可。

## 四、PDF 生成技术方案

### 4.1 技术选型
- **Python + reportlab**（服务端/本地脚本生成，中文支持好、版式可控）
- **Pillow**：读取截图尺寸以按比例缩放
- 备选：若需所见即所得，可用 HTML + wkhtmltopdf / Puppeteer；但 reportlab 排版精度更高、依赖更少。

### 4.2 安装
```bash
python -m pip install reportlab pillow pypdf
```

### 4.3 三份文档的脚本与产物
| 文档 | 脚本 | 产物 | 约页数 |
|------|------|------|--------|
| 操作手册 | `build_manual.py` | `HydroLab-操作手册.pdf` | 17 |
| 需求文档 | `build_requirements.py` | `智能泵站全工况科研虚拟仿真平台-需求文档.pdf` | 16 |
| 测试用例 | `build_testcases.py` | `智能泵站全工况科研虚拟仿真平台-测试用例.pdf` | 24 |

三个脚本共用同一套字体注册、配色、样式与页面装饰函数，仅正文 story 不同，确保三份 PDF 风格完全一致。

### 4.4 核心代码骨架（直接复用）
```python
from reportlab.platypus import (BaseDocTemplate, PageTemplate, Frame, Paragraph,
    Spacer, Image, PageBreak, Table, TableStyle, KeepTogether, NextPageTemplate, ListFlowable, ListItem)
from reportlab.lib.pagesizes import A4
from reportlab.lib.units import mm
from reportlab.lib import colors
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.ttfonts import TTFont
from PIL import Image as PILImage

# 字体注册（见 1.3）
# 配色（见 1.2）
# 样式：H1/H2/H3/BODY/BULLET/CAP/COVER_T/TOC/TBL/TBLB

# 图片按比例缩放到内容宽度
def img(path, max_w=CONTENT_W, max_h=150*mm):
    with PILImage.open(path) as im: iw, ih = im.size
    r = min(max_w/iw, max_h/ih)
    return Image(path, width=iw*r, height=ih*r)

# 图 + 图注打包，避免跨页拆散
def fig(path, caption):
    return KeepTogether([img(path), Paragraph(caption, CAP)])

# 提示框（左色块标题 + 右浅蓝正文）
def info_box(title, text): ...

# 标准表格（深蓝表头 + 隔行底色 + 跨页重复表头）
def std_table(data, colWidths): ...

# 需求条目表（需求文档专用）
def req_table(rows): ...   # 编号|描述|优先级|状态

# 测试用例块（测试用例专用）
def tc_block(tc_id, title, pre, steps, expected, priority, cover): ...  # 标题条+属性表+步骤表

# 双页面模板：cover_bg（满版深蓝） + normal_bg（页眉页脚）
doc = BaseDocTemplate(OUT, pagesize=A4, ...)
doc.addPageTemplates([
    PageTemplate(id="cover", frames=[frame_cover], onPage=cover_bg),
    PageTemplate(id="normal", frames=[frame_normal], onPage=normal_bg),
])
# 故事流：封面 → NextPageTemplate("normal") → PageBreak → 目录 → 各章 → 附录
doc.build(story)
```

### 4.5 易踩的坑
- **TTC 字体**必须传 `subfontIndex=0`，否则注册失败。
- **页脚页码**用 `doc.page` 而非 `doc.page-1`，否则与目录索引差 1。
- **目录页码**需与最终页脚一致：生成后用 `pypdf` 提取每章实际页码，回填目录，再重跑一次。脚本：
  ```python
  import pypdf, re
  r = pypdf.PdfReader(OUT)
  for i, p in enumerate(r.pages, 1):
      t = p.extract_text() or ''
      for m in re.findall(r'(第[一二三四五六]章[^\n]{0,12}|附录\s*[AB][^\n]{0,8})', t):
          print(i, m.strip()[:20])
  ```
- **图片缩放**必须读真实尺寸按比例算，否则变形；截图文件若为 0 字节（截图失败）会报 `UnidentifiedImageError`，需重新截。
- **图与图注**用 `KeepTogether` 包裹，防止图在一页、注在下一页。
- **长表格**用 `Table` + `ROWBACKGROUNDS` 隔行底色 + `repeatRows=1` 跨页重复表头，提升可读性。
- **测试用例块**用 `KeepTogether` 包裹（标题条+属性表+步骤表），避免一个用例被分到两页。
- **大脚本拆分**：若单次 `Write` 内容过大失败，可拆成 `_p1.py/_p2.py/...` 多个 UTF-8 小文件，再用纯 ASCII 的 Python 脚本 `io.open(..., encoding="utf-8")` 拼接合并，避免 PowerShell `Add-Content` 默认 GBK 编码导致中文乱码。

## 五、给 AI 的协作流程（复用本风格产出三份文档）

在别的软件项目里，按以下步骤让 AI 产出同风格的三份验收文档：

1. **提供上下文**：把本文件 + `build_requirements.py` / `build_testcases.py` / `build_manual.py`（作为代码模板）+ 目标软件的功能清单/参数要求喂给 AI。
2. **提供截图**：用浏览器 MCP 或人工截好目标软件各功能态截图，命名 `01_xxx.png` 放到 `manual/shots/`。操作手册每章配图，需求文档关键模块配图，测试用例少量界面图。
3. **告知调整点**：
   - 软件名、副标题、品牌落款、三份文档的页眉副标题
   - 三份文档的章节清单（按目标软件功能模块列）
   - 配色是否沿用深海军蓝（可换主色 Hex）
   - 需求文档：功能需求条目（FR-XX）与附录追踪矩阵的参数条目对应
   - 测试用例：用例编号（TC-XXX）与需求编号（FR-XX）一一对应
   - 附录内容（资源清单、公式、参考文献、术语表、缺陷分级）
4. **让 AI 产出**：基于三个 build 脚本改写出对应脚本，调整章节文本与图片引用，运行生成 PDF。
5. **校对页码**：用 4.5 的 pypdf 脚本提取每章实际页码，回填目录，重跑生成，确保目录与页脚一致。
6. **通读核对**：检查中文显示、图片清晰度、目录页码与页脚一致性、图注/用例编号连续、追踪矩阵全覆盖。

### 提示词模板
```
参考《操作手册制作指南.md》和 build_requirements.py / build_testcases.py / build_manual.py
的风格与代码结构，为我的软件「<软件名>」生成三份图文并茂的验收文档 PDF：
需求文档、测试用例、操作手册。
功能清单/参数要求：<粘贴功能模块或参数条目>
截图已放在 manual/shots/，命名为 01_xxx.png ...
要求：
- 三份文档共用深海军蓝(#0B2545)+科技蓝(#1277D6)配色与微软雅黑字体
- 封面 + 目录 + 章节正文 + 附录的结构
- 操作手册每章配 1 张截图，图注格式「图 X-Y 说明」
- 需求文档含功能需求条目表（FR-XX）与附录需求追踪矩阵
- 测试用例每条含编号/前置/步骤/预期/关联需求，附录含用例汇总与缺陷分级
- 页脚页码与目录一致
输出 build_<文档名>.py 并运行生成 PDF，最后用 pypdf 校对目录页码。
```

## 七、成套交付要点

- **风格统一**：三份 PDF 共用封面、页眉页脚、配色、字体、表格、提示框，成套交付观感一致。
- **编号互通**：需求 FR-XX ↔ 测试用例 TC-XXX ↔ 追踪矩阵参数条目，三者编号互相对应，验收时可双向追溯。
- **可复现**：三个 build 脚本即"文档源码"，随软件迭代重跑即可同步更新，避免文档与软件脱节。
- **图文并茂但不冗余**：操作手册重图、需求文档图表均衡、测试用例重表，各司其职。
